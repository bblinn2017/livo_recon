This file lists every configuration option that the livo_recon ROS node reads. For each option it gives the type, the default that the code uses when the key is absent, the value in `config/ntu_viral.yaml`, what the option does according to the code that reads and uses it, and where in the source it is read and used.

It was generated by reading the code at git HEAD of /tmp/wk (`git -C /tmp/wk rev-parse --short HEAD` gives e6d1bf2), on 2026-10-15. Nothing was compiled or run. Descriptions come from the code that reads and uses each key, not from key names or yaml comments. Where a yaml comment and the code disagree, the meaning column says so. "Not set" in the yaml column means `config/ntu_viral.yaml` does not contain the key; for such keys the other files in `config/` that do set it are listed. Values in the yaml column were read from the files named.

Keys are written with a slash in the code and in ROS (for example `voxel_map/map/voxel_size`) and with dots in job override files (`voxel_map.map.voxel_size`). The node refuses to start when the parameter server holds a key under the node namespace that nothing read; the check runs last in `LivoReconNode::loadParameters`. Removed or renamed keys are refused earlier, with their own message. Enumerated options that go through the config resolver reject an unrecognised value and the run is refused; options that are compared with plain string tests are marked "unvalidated" and the table says what an unrecognised value does. Keys that are read only in one scope (a mode, a switch) are refused when set while that scope is not selected; each such key says so.

The key list is the union of the keys found by flattening every `config/*.yaml` (149 keys) and the keys found by reading the parameter calls in `src` and `include/livo_recon`. The harness override keys that the node reads are included in their branches (`eval/state_trace_en`, `eval/pose_cov_trace_en`, `eval/imu_first_scans_en`, `eval/state_trace_run_id`, `diagnostics/frame_window_log`, `outputs/odom/export`, `outputs/debug_log_dir`, `data_queues/log_lidar_msgs`, `lio/first_frame_dump_frames`, `lio/line_rows_log_en`, `lio/zsq_log_en`, `voxel_map/map/snapshot_post_calibration`, `voxel_map/map/snapshot_frames`, `voxel_map/plane/plane_fit_reasons_en`, `common/offline_bag_path`). (`config/experiments/` -- unreferenced, stale override snippets from a round before R97A, several setting keys Q4 has since removed -- was deleted in R97A's config cleanup pass, not part of the key list even when it existed.)

## The R97 default set

`config/ntu_viral.yaml` carries the R97 default set: the map backend is `binned` with `bin_size_fraction` 0.25 and `cov_mode` average; the voxel size is 0.425 with `max_layer` 2; `min_init` and `min_update` are 5 and 5; the starting covariance P0 has exactly zero position and velocity variance; the process noise model is isotropic; the line residuals are on with form hard, rule absolute, rows per_normal and variance plane_equivalent; and VIO is disabled (`vio/enable` false). The other yaml files in `config/` keep different values for several of these keys, and the `*_no_overrides.yaml` files are empty maps; the "not set" cells name those other values where they exist. Code defaults (the third column) are the values used when a key is absent and are in several places different from the R97 set.

## calib

Calibration is mandatory in this build: the node does not start estimating until `calib/stationary/num_samples` IMU samples have been collected from the first image windows, the attitude has been aligned to the mean specific force, the noise floor has been measured and the initial covariance (P0) has been built. The keys `calib/use_calib`, `calib/use_calib_var`, `calib/use_calib_bias`, `calib/num_samples`, `calib/stall_calls_max` and `calib/bootstrap/point_cov` are refused with an error if set (see Removed keys).

### imu/process_noise

The IMU process noise has three parts. The accelerometer and gyroscope step variances come from `imu/process_noise/model` (fixed numbers, or the stationary floor plus a motion-dependent term); the two bias coordinates grow by a random walk or a Gauss-Markov model (`imu/process_noise/bias_model`); an optional scalar gain computed on the LiDAR side multiplies the step variances on the next scan (`imu/process_noise/gain/*`). `imu/q_alpha_acc`, `imu/q_alpha_gyr` and `imu/q_alpha_bias` scale the three resulting covariance blocks.


| key | type | code default | value in config/ntu_viral.yaml | meaning | read at |
|---|---|---|---|---|---|
| `imu/process_noise/model` | string enum | "fixed" | `isotropic` | Source of the per-IMU-step accelerometer and gyroscope noise variance. "fixed": the numbers in imu/process_noise/fixed/*. "isotropic": the stationary-calibration variance floor (times the floor scale) plus a motion term built from one shared excitation energy (squared norm of the gravity-removed acceleration, or of the bias-corrected angular rate, divided by 3) after subtracting the mean floor. "axis_aware": the same with the energy and the floor taken per axis. Both dynamic models low-pass the energy with imu/process_noise/motion/beta, scale it by the square of the scale key, and cap it.
